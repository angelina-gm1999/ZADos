ZADOS FRONTEND INTERFACE SPECIFICATION
Target engine: Godot 4.x
Backend: Python FastAPI/WebSocket server wrapping ZADOS
Date: 2026-03-18

================================================================================

0. ARCHITECTURE OVERVIEW
================================================================================

COMMUNICATION LAYER

ZADOS is a synchronous Python library with no built-in networking. The Godot
frontend communicates with a thin Python bridge server that wraps the ZADOS
orchestrator. Two transport mechanisms:

  - HTTP REST  -- session lifecycle, memory CRUD, workspace queries
  - WebSocket  -- per-turn streaming (phase completion events + token streaming)

  Godot Frontend
      <-> HTTP REST + WebSocket (localhost)
  Python Bridge Server (FastAPI)
      <-> in-process function calls
  ZADOS SessionOrchestrator / AnswerPipeline
      <-> in-process
  NeurochemicalEngine / Memory / CognitiveEngines

GLOBAL LAYOUT

The UI is a workspace switcher -- one primary area that changes based on the
active workspace, with a persistent top navigation bar. No multi-window MDI;
workspaces are full-panel scene swaps.

  +-------------------------------------------------------------+
  |  NAV BAR: [Conversation] [Memory] [Learning] [Dev] [Map]    |
  +-------------------------------------------------------------+
  |                                                             |
  |              ACTIVE WORKSPACE SCENE                         |
  |                                                             |
  +-------------------------------------------------------------+

PERSISTENT ACROSS ALL WORKSPACES:
  - Session status indicator (branch A/B/C, turn count, active mode token)
  - Neurochem pulse strip -- a thin bar at the bottom showing the 5 core NT
    levels as colored segments that subtly animate with each turn
    (DA=gold, 5HT=teal, NE=orange, GABA=blue, GLU=red)

  - Each AI response bubble has a small expand arrow -> opens an inline detail

  - During generation: Phase progress indicator replaces the AI bubble until

  - Send button

Backend data sources:

1.3 RIGHT PANEL -- NERD STATS (3 TABS)

TAB 1: REWARD SYSTEM STATUS

Populated from PipelineResult.phase5_result after each turn.

  Current Mode Header (always visible, top of tab)
  - Large mode token badge -- e.g. Normal / LearningMode_M1 / SleepMode_REM /
    SleepMode_Dream / Homework / SelfReflective

    session.initial_mode before first turn
  - Color-coded by mode family:
      Normal=gray, Learning=blue, Sleep/REM=indigo, Dream=purple,
      Homework=amber, SelfReflective=teal
  - Sub-label: human-readable description (e.g. "M1 -- Teach me something",
    "REM -- Retroactive consolidation")

  Active Reward Profile
  - Profile name badge (e.g. regular_input, curiosity_driven)
  - Learned domain weights vs static profile weights -- side-by-side bar
    comparison
      - Domains: logic, ethics, innovation, attunement
      - Static weight (gray bar) + learned adjustment overlay (color bar)
      - Source: session.learned_domain_weights vs
        PROFILE_REGISTRY[profile_name].domain_weights

  Tonic Pathway Result
  - Domain evaluation scores (radar/spider chart): logic, ethics, innovation,
    attunement
  - urgency_risk gauge (0.0--1.0)
  - meta_directive: ALLOW (green) / SUPPRESS (red) / ABSTAIN (yellow) + reason

  Phasic Pathway Result
  - NT release drives from ExtractorResult (bar chart, top 6 NTs by delta)
  - feedback_params receptor adjustments (collapsible list)

  NT Signals Applied (next turn)
  - Preview of nt_signals from Phase 5 that will modulate the next turn

TAB 2: NEUROCHEM ACTIVITY LOG

Rolling timeline log -- one entry per completed turn, expandable.

  Per-turn entry shows:
  - Turn index + timestamp
  - NT snapshot (30 values) displayed as horizontal heatmap strip
      - Rows: groups (Dopaminergic, Serotonergic, Noradrenergic, Cholinergic,
        Opioid, Endocannabinoid, Stress, GABAergic, Glutamatergic, Histaminergic)
      - Color: blue (low) -> neutral (mid) -> red (high)
  - Oscillatory band snapshot: delta/theta/alpha/beta/gamma/sigma as mini bar
  - 11 NeurochemicalMetrics as labeled gauges:
      motivation, empathy, cognitive_rigidity, fatigue, precision, openness,
      anxiety, social_engagement
      (sleep metrics: dream_permissiveness, consolidation_depth,
      narrative_plasticity -- shown grayed out during waking)
  - Mode token for this turn

  Clicking a turn entry expands the full NT values and shows the differential
  from the previous turn (which NTs moved most).

  Backend data sources:
    state.modulation.nt_snapshot         (Dict[str, float], lowercase keys)
    state.modulation.osc_snapshot         (Dict[str, float])
    state.modulation.metrics_dict         (Dict[str, float])
    state.modulation.reward_profile_name
    state.modulation.mode_token

TAB 3: COGNITIVE ENGINE RESULTS

Per-turn display of which engines ran and their outputs.

  Layout:
  - Turn selector (dropdown or prev/next arrows)
  - Engine grid: 29 tiles, each showing engine number + name
      - Green border = ran this turn
      - Gray border  = skipped
      - Clicking a tile opens a result inspector panel

  Engine result inspector:
  - Raw result dict displayed as collapsible JSON tree
  - For key engines, structured display:
      E8  (Semantic Facets):    ranked facet list with scores
      E18 (Entity Extraction):  subject-relation-object triples as small graph
      E19 (Pattern Detection):  detected pattern list with confidence
      E23 (Intent Detection):   intent archetype + confidence bar + coefficients
      E28 (Emotion Detection):  28-emotion radar chart, 7 functional groups
      All others: JSON tree

  Engine weights display:
  - Current engine_weights dict as ranked bar list (which engines were
    prioritized this turn)

  Backend data sources:
    state.dispatch.engine_results    (Dict[int, Dict])
    state.dispatch.engines_run       (List[int])
    state.dispatch.engines_skipped   (List[int])
    state.modulation.engine_weights  (Dict[str, float])
    state.dispatch.e28_result
    state.perception (Phase 1 structured outputs)

Backend data sources:

LTMM / KNOWLEDGE

Sub-tabs: Library | Notebook | Knowledge Maps | Lessons | Academic Buffer |

  Library:

  - Ingested document list with title, source, date, tag list
  - Search bar (semantic search against library)
  - Each document card has: preview excerpt, tags, delete button

  Notebook:
  - List of notebook entries from knowledge/notebook/store.py
  - "New Entry" button -> inline rich text editor
  - Tags, title, manual entry
  - Also shows AI-written notebook entries (pipeline-triggered writes)

  Knowledge Maps:
  - Preview panel linking to the Cognitools / Knowledge Map workspace (Sec. 5)
  - Shows count of maps and list of map names
  - "Open in Map Editor" button -> switches to Map workspace with that map loaded

  Lessons:
  - List of lessons stored in knowledge/lessons/store.py
  - Lesson card: title, source pipeline, date, content excerpt
  - Generated by Learning pipelines -- read-only here, but deletable

  Academic Buffer:
  - NOT a file upload area -- this is a stagnated-concept queue automatically
    populated by the Homework pipeline. No manual input.
  - Two entry sources (both written by HomeworkPipeline Phase 3):
      1. Unresolved contradictions from Phase 2 dialectic processing that
         couldn't be reconciled
      2. Questions from the UnsolvedBuffer that have stagnated past the

  - Each entry (AcademicBufferEntry) shows: concept formulation text, subject

  - Status column: Pending / Dream Candidate / Resolved
  - "Mark Resolved" button + resolution note field
  - Dream candidate entries are highlighted -- picked up by REM (domain weight
    boosting) and deprioritized but available to Dream pipeline
  - Filter by: subject category, resolved/unresolved/dream-candidate,

  - Raw data store used by cognitools (E9 AtomSpace, etc.)
  - Read-only JSON browser for inspection

LTMM / UNSOLVED

Source: memory/long_term/thoughts/unsolved_buffer/store.py +

  - Homework processing -- HomeworkPipeline Phase 3 writes unresolved
    contradictions back as new questions; stagnated questions get tagged
    dream_candidate + origin:academic after 5 failed resolution attempts

Priority queue display (sorted by urgency -> oldest first -> longest stagnation):

  - origin:academic tag -> badge (from homework, deprioritized in Dream)

  - "Mark Resolved" button + partial answer entry
  - "Send to Conversation" button -> pre-fills input with question text
  - "Send to Self-Reflective" -> triggers Self-Reflective Query on this question

Cluster view toggle: Groups questions by shared tags (tag-based clustering
from cluster_questions())

      validated lessons count, contradictions resolved/unresolved, questions

5. COGNITOOLS / KNOWLEDGE MAP WORKSPACE
================================================================================

Decision on placement: This is a TOP-LEVEL WORKSPACE (5th nav item), not buried
in LTMM. Rationale: it's interactive and co-usable with conversation (both can
be open via split view or window tear-out in the future). A quick-access button
in the LTMM / Knowledge / Knowledge Maps tab links here.

Source: cognitive_engines/cognitools/atomspace_engine.py (E9 -- AtomSpace-Lite)

5.1 WHAT IT IS

E9 implements an OpenCog AtomSpace-inspired typed hypergraph. Nodes are
concepts/predicates/schemas/variables. Links are typed relations (Inheritance,
Similarity, Evaluation, Hebbian, Implication, etc.). Every atom has a
TruthValue (strength + confidence) and AttentionValue (STI short-term
importance, LTI long-term importance). The map is live -- it updates during
processing as E9 runs in Phase 3.

5.2 LAYOUT

  +-------------------------------------+---------------------+
  |                                     | INSPECTOR PANEL     |
  |   HYPERGRAPH CANVAS                 |                     |
  |   (2D force-directed node graph)    | Selected atom:      |
  |                                     |  - Type             |
  |   [nodes as circles]                |  - Name             |
  |   [links as labeled edges]          |  - TruthValue       |
  |                                     |  - AttentionValue   |
  |                                     |  - Outgoing links   |
  |                                     |                     |
  |                                     | SEARCH              |
  |                                     | FILTER BY TYPE      |
  |                                     | ADD NODE / LINK     |
  +-------------------------------------+---------------------+
  | TOOLBAR: [Zoom] [Layout] [Filter] [Map Selector] [Import] |
  +-----------------------------------------------------------+

5.3 CANVAS BEHAVIOR

Node rendering:
  - Node type -> shape:
      ConceptNode   = circle
      PredicateNode = diamond
      SchemaNode    = hexagon
      VariableNode  = dashed circle
      NumberNode    = square
      GroundedNode  = star
  - TruthValue strength   -> node fill opacity (0.0=faint, 1.0=solid)
  - TruthValue confidence -> node border thickness
  - AttentionValue STI    -> node size (higher STI = larger)
  - AttentionValue LTI    -> node glow/halo intensity
  - Color by semantic category (auto-clustered by name prefix or manual tag)

Link rendering:
  - Link type -> line style:
      InheritanceLink  = solid arrow (directed)
      SimilarityLink   = double-headed arrow (symmetric)
      HebbianLink      = dashed line (symmetric)
      ImplicationLink  = thick solid arrow
      EvaluationLink   = dotted arrow
      AndLink/OrLink/NotLink = connector nodes with operand lines
  - TruthValue strength -> line opacity
  - Link labels show type name (toggleable)

Interaction:
  - Click node        -> select, show inspector
  - Drag node         -> reposition (layout frozen for that node)
  - Double-click node -> expand neighborhood (all directly connected atoms)
  - Right-click       -> context menu: Add Link From Here, Delete Node, Pin/Unpin
  - Scroll to zoom, drag canvas to pan
  - Auto-layout: force-directed (Godot spring simulation) -- "Re-layout" button

Live updates:
  - When a turn completes, newly written/updated atoms pulse briefly
  - STI values animate as they decay or boost
  - New HebbianLinks appear with a brief "spark" animation

5.4 INSPECTOR PANEL

  - Atom type badge
  - Name / value
  - TruthValue: strength slider (editable) + confidence slider (editable)
  - AttentionValue: STI numeric input + LTI numeric input
  - Outgoing links list (clickable to navigate to linked atom)
  - Incoming links list
  - "Delete Atom" button (with confirmation)
  - "Add Link" button -> opens link creation dialog

5.5 TOOLBAR

  - Map Selector   -- dropdown of all saved maps from
                      memory/long_term/knowledge/knowledge_maps/store.py
                      + "New Map" option
  - Filter by Type -- checkboxes for each AtomType (toggle visibility)
  - Search         -- find atom by name substring, centers canvas on result
  - Import         -- paste JSON/text to batch-add atoms (natural language
                      parsing via AI -> calls POST /cognitools/atomspace/parse)
  - Export         -- download map as JSON
  - Layout toggle  -- force-directed vs hierarchical vs radial

5.6 CO-INTERACTIVE USE WITH CONVERSATION

A "Live Link" toggle in the toolbar. When enabled:
  - E9 runs in Phase 3 each turn (already the case when engine is active)
  - After each turn, canvas auto-updates with new/modified atoms from that turn
  - "Changes this turn" mode highlights only atoms touched in the last turn
  - User can pin interesting nodes and see how they evolve across turns

"Inject Concept" quick action:
  - Right-click a node -> "Send to Conversation" -> pre-fills input with:
    "Let's talk about [node name]"
  - Creates conversational continuity between visual map and dialogue

Backend data sources:
  GET    /cognitools/atomspace/atoms          -> full atom list for session
  GET    /cognitools/atomspace/atoms/:id      -> single atom details
  POST   /cognitools/atomspace/atoms          -> add atom manually
  PUT    /cognitools/atomspace/atoms/:id      -> update TruthValue/AttentionValue
  DELETE /cognitools/atomspace/atoms/:id      -> delete atom

  Phase 4 [Journal Write]                              [----------]  0%

    based on NT thresholds
  - Domain weight deltas being applied: shows which weights are being raised/
    lowered and by how much
    (e.g. frustration -> +logic, +ethics)
  - Academic Buffer scan: count of AcademicBufferStore dream-candidate entries
    detected -> displayed as origin count contribution to domain weight boosts
    (academic entries boost logic weight)

Phase 2 panel -- Consolidation:
  - MTMM packets queued for promotion -> LTMM, listed with emotional

  - Packets being left to decay (below threshold)

Phase 3 panel -- NT State:
  - Live neurochem metrics with REM prescribed baselines overlaid as target

  - E27 containment monitor: live +-0.25 tolerance bands per NT; runaway

Phase 4 panel -- Journal Write:
  - Journal entry prose streaming in real-time as it's generated

6.2 DREAM WORKSPACE

Candidate queue panel -- 3 priority tiers (sorted by origin):

      confusion -> +logic
      wonder    -> +innovation
      perplexed -> +logic +innovation

Narrative plasticity gauge (prominent, from NeurochemicalMetrics)
