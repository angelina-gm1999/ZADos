Design Process: Pre-Implementation
The architecture was designed on paper over an extended period before a single line of production code was written. The design process followed a specific sequence that shaped the final system.
The starting point was a basic question: what would it take to give an AI system actual reasoning beyond pattern completion? The first pass was improvised. Multiple language models and logic components went into a single file with no pipeline concept and partial functionality, and the architectural requirements broke it. That failure was informative. It made clear that the system needed a principled structure.
What followed was a research and design phase with two parallel tracks. The first was outward-facing: studying what artificial intelligence means at a cognitive level, what components compose a mind, what cognitive science and neuroscience offer as reference models. The second was inward-facing: introspective analysis of thinking and learning processes as a direct reference for modeling cognition. The author has been doing metacognition consciously since early childhood, which made this second track unusually productive. Mapping cognitive processes into a pipeline structure turned out to be more tractable than expected precisely because the raw material was already well-observed.
From this phase came three foundational design decisions.
The first was bio-inspired neurochemical modeling, chosen specifically because biological neurochemistry is the only empirical reference we have for fluid, adaptive, contextually sensitive cognition.
The second was a three-tier memory architecture mirroring human short, mid, and long-term memory structures.
The third was a functional emotion taxonomy: 46 emotional states defined by cognitive function. Each state was specified in terms of what it does in a reasoning system, what it triggers, what it regulates, and how it maps onto neurochemical dynamics. Every emotion was given full receptor subtype mappings, oscillatory signatures, pharmacodynamic models, and memory layer interactions before any implementation began.
This entire design phase produced approximately 900 pages of notes and specifications, the raw material from which the implementation was later built.
After the design phase, attempts were made to find support or funding to build the system. These went unanswered. So the author taught herself to code through a separate, unrelated project and then built ZA-DOS herself, translating the paper specifications into working code layer by layer, reviewing and refining each spec before implementation and iterating between layers to connect and integrate everything correctly.
