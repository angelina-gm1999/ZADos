## Where to Start

Different readers will want different entry points.

**If you're new to the project** — start with [`TECHNICAL_SPECIFICATIONS/COMPREHENSIBLE_SPECS/`](TECHNICAL_SPECIFICATIONS/COMPREHENSIBLE_SPECS/). These are accessible overviews of each architectural layer, written for readers who want to understand the system without reading code.

**If you're evaluating safety and alignment** — start with [`ETHICS_SAFETY_ALIGNMENT/`](ETHICS_SAFETY_ALIGNMENT/). The alignment architecture, deployment boundaries, dual-use analysis, and psychosocial risk assessment are all here.

**If you're considering collaboration or support** — start with [`STATE_NEXTSTEPS_CALLFORACTION/`](STATE_NEXTSTEPS_CALLFORACTION/). This folder covers where the project is, where it could go, what remains unsolved, and what kind of support is needed.

**If you want to understand the project's history** — start with [`DEVELOPMENT/`](DEVELOPMENT/). The origin report traces the system from its single-file prototype through to the current architecture. The developer logs document every implementation session.

## Relationship to Source Code

The source code and test suite have their own READMEs in `ROOT/src/` and `ROOT/tests/` respectively. This documentation folder covers design rationale, ethical analysis, research grounding, and project direction — the context that surrounds the code but lives outside it.

For the implementation itself, see the source code README. For test coverage details, see the test suite README and test suite report.
